# SEO guide

Plain-language summary of how SEO works in this app, what is already done, and what the owner must still decide or supply. Code: `config/seo.php`, `app/Support/Seo.php`, `app/Http/Middleware/SeoRobotsHeader.php`, `app/Http/Controllers/SeoController.php`, `resources/views/components/seo.blade.php`. Tests: `tests/Feature/SeoTest.php`.

## How it works

- **Safe default:** every page is `noindex` (response header `X-Robots-Tag` plus `<meta name="robots">`). A page is only indexable if its route name is in `indexable_routes` in `config/seo.php` **and** the app runs in an environment listed in `index_environments` (`production` only). So staging, local and every private area can never show up in Google by accident.
- **Public pages today:** `home` (`/`), `login`, `register`.
- **Public page tags:** `<x-seo>` adds canonical URL (built from `APP_URL`, query strings ignored), description, Open Graph, Twitter card and JSON-LD. The home page emits `Organization` + `SoftwareApplication` with one `Offer` per active plan, built from real plan data.
- **`/robots.txt` and `/sitemap.xml`** are generated by the app (the old static `public/robots.txt` was removed). Outside production, robots.txt says `Disallow: /`. In production it blocks private paths and points to the sitemap.
- **Adding a public page:** give the route a name, add it to `indexable_routes` (and `sitemap_routes` if it should be listed), use a unique `<title>`, one `<h1>`, and `<x-seo :title :description />`. Rule is also in the `seo-checklist` skill.

## Needs the owner (PENDING)

1. **Production domain.** Set `APP_URL=https://<real-domain>` in the production `.env`. Canonical, sitemap and JSON-LD use it. A wrong value here is the most damaging SEO mistake.
2. **Default share image.** A 1200x630 JPG/PNG (set `default_image` in `config/seo.php`, or upload a logo in site settings). Without one, shares show no image and the Twitter card is the small one.
3. **Site settings content:** fill `meta_title`, `meta_description`, `email`, `phone`, social URLs in admin settings. They feed the tags and the Organization schema.
4. **Company apply pages (`/{slug}/apply`)** are `noindex` for now. Decide whether carriers want these to rank (for example "drive for X"). If yes, whitelist that route name; the step pages and status pages stay private either way.
5. **Marketing content.** The home page is one page. To rank for searches like "DOT driver qualification file software" you need real content pages (features, pricing, guides). This is a content job, not just code.

## After launch (one time)

1. Verify the domain in Google Search Console and Bing Webmaster Tools, then submit `https://<domain>/sitemap.xml`.
2. Check the live home page with Google's Rich Results Test and the URL Inspection tool.
3. Run Lighthouse (mobile) on `/`; keep Performance and SEO above 90. Known cost: the third-party chat widget and font kit load on public pages.
4. Redirect `http` to `https` and `www` to one host at the server.

## Known gaps (not fixed here)

- Unused TailAdmin template views (`signin`, `signup`, `buttons`, `index.html` and similar in `resources/views`) are not routed. They are harmless but should be deleted.
- `/pricing/plans` is behind login, so prices are only public on the home page.
- `layouts/main-layout` (logged-in area) still prints description/Open Graph tags from site settings. Robots keeps them out of Google.
